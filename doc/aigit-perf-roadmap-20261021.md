# aigit 性能优化路线（2026-10-21 初稿）

> 状态：**设计稿**。没有任何代码改动；本文所有「预估」都不是实测。
> 锚定：aigit `D:\project\aigit`，HEAD 与工作区快照见 §8。
> 口径：`[实测]` = 有命令、有 rc、可复现；`[预估]` = 由实测外推、**尚未验证**；`[待测]` = 连外推都没有，P0/P1 出数才能定。

---

## 0. 目的与非目标

**目的**：把 aigit 的响应时间砍到「单机单仓、离线可用」场景下的地板附近，并且**每砍一刀都有可复现的数字**。

**非目标**（明确不做，防止路线膨胀）：

- 不换掉 `http.server`、不引入 asyncio 网络栈、不装第三方依赖；
- 不引入 Spanner/WAL/packfile 替代品/多级缓存拓扑这类「3 万 merges/day 才划算」的基建
  （Scion 的前提是「单一权威副本 + 服务端无限扩容」，aigit 的前提是「一台机器 + 离线 + fail-closed」）；
- 不为性能牺牲任何一条已建立的 fail-closed 守卫（见 §5 红线）。

**收益的计量单位**：**砍掉第 N 次 git 子进程**。Windows 上每次子进程约 40ms 地板价，
所以「一次请求 spawn 了几次」近似等于「这次请求最少还要花多少毫秒」。倍数神话不进本文。

### 1.1 成本结构

| 项 | 数字 | 出处 |
|---|---|---|
| 裸 `git --version`（什么都不干） | **39.71ms** median（36.30–44.10） | `aigit-A5-scale-perf.md` §2.2 L173 |
| `rev-parse --abbrev-ref` 全程 | **42.42ms** median（40.17–54.35） | 同上 L174 |
| 老 `status()` = 2 次子进程 | **96.0ms** = v1 扫描 51.6 + `symbolic-ref` 44.0（账闭合） | `aigit-E13-perf-layer.md` §3.1 L171 |

由于地板价恒定，**spawn 计数**是可排序、可比较的稳定量，墙钟会随机器漂。

## P0 · 可复现基准台

**问题**：现有性能数字一部分不可复现（`aigit-dist.md` §5 那组 102.1/139.7ms 的脚本已丢），
`aigit_perf.py` 文首明写「我不是基准，一行计时代码都没有」。没有基准台，后续每阶段都只能自说自话。

**产出**：`D:\project\aigit\bench_aigit.py`（纯 stdlib，单文件）
- 造仓：1k / 5k / 10k 受跟踪文件 + 200 untracked + 1 个 5000 行文件，全部建在 `%TEMP%`；
- 端点电池：`/api/status`（全量/分页）、`/api/log?limit=30`、`/api/history/blame`、
  `/api/diff`、`POST /api/stage`（100 路径、3000 路径两档）；
- 每项 9 次，记 median/min/max + 响应字节数 + `git --version` 校准 median；
- JSON 落盘（`--out`），含 `platform.platform()`、`git --version` 字符串、样本数；
- **不判断好坏、不给优化建议**——只量。

**判据**
1. `--quick` 跑通 rc=0，输出含全部字段；
2. 校准段：`/api/status` median 与 `裸 git status median + 40ms` 相差 ≤ 60ms，打印 PASS/FAIL；
3. 基线 JSON 落 `doc/` 证据目录，**文件名带 commit sha 前 8 位**（E13 的教训：锚定不清的数字会腐坏）；
4. 全程不触碰真实仓（`--root` 只指 `%TEMP%` 下的生成仓）。

**停机条件**：校准段 FAIL 且找不到原因 → 不进入 P2（先修量尺）。

## P1 · 每请求子进程计数与排行

**问题**：91 个调用点 ≠ 91 次/请求。不知道排行，P2 就是盲改。

**产出**：计数原型（先落 scratch，验证后再决定进不进仓）
- 在引导脚本里包 `Repo._run_full`，记录每次调用的子命令；
- 对 `find_test_gaps.py` 的 30 条 `PROBE_PATHS` + 4 条写/重端点逐条请求，得到
  `路径 → spawn 次数 → 子命令序列 → HTTP 码`；
- 按「(spawns−1) × 40ms」排序落 JSON。

**判据**
1. 排行表落盘，样本数 ≥ 1（每端点串行测 3 次取众数，低于 3 次不算）；
2. 抽 3 条与 E13 已知账对得上（如 status=1 次）；
3. `find_test_gaps` 零提及仍为 0（若加响应头，键面不得变化）。

**停机条件**：排行里最大 spawn 也只有 2 → P2 没有肉，直接跳到 P3。

## P2 · 逐端点合并/去重 git 调用

**手法**（按 P1 排行从高到低做）：
1. **请求级 memo**：同请求内对同一 `(子命令, 参数)` 只 spawn 一次（请求结束即丢，无失效问题）；
2. **一次出多份答案**：如 `status --porcelain=v2 --branch` 已带 `# branch.head`，检查是否还有单独 spawn 查分支；
3. **合并只读查询**：`rev-parse` 类互不依赖的查询合并为一次 `git rev-parse --git-dir --is-bare-repository --show-toplevel`（按需）。

**预估收益**：**每砍一次 spawn ≈ −40ms/请求** `[预估]`，依据是 §1.1 的闭合账（±2.5ms）。
不做「按端点整体加速 X%」这种无依据的承诺。

**判据**
1. P0 基准台上该端点 median 下降 ≥ 30ms（否则不算赢）；
2. 六套件全绿 + 28/28 变异 + 33/33 探针；
3. 语义零变化：同一请求的响应键集与值类型前后逐对比对（不含时间戳类字段）；
4. 该端点在新基准 JSON 里留 before/after 两份。

**停机条件**：同一端点降幅 < 15% 且 spawn 数已到 1 → 记「已到地板」，转 P3。

## P3 · sha 键记忆化（「算过的永不重算」的单机版）

**原理**：结果只由不可变输入决定 ⇒ 可以无限期缓存，且缓存**不需要跨节点协调**。

**允许缓存的**
- `subject_of(sha)`、`short(sha)` 等以 sha 为唯一输入的派生值 —— HEAD 不动就命中，动了自己失效；
- blame：键 `(epoch, HEAD_sha, rel)`。

**绝对禁止缓存的（红线）**
- `status` / `dirty` / 工作区 diff / 任何「工作区状态」——它们是 fail-closed 守卫的输入，
  缓存等于给守卫喂过期数据。**这条不设开关、不设例外。**

**失效规则（唯一一条，够用）**：任何写端点（stage/unstage/discard/reset/commit/amend/merge…）
成功返回时 `epoch += 1`。不做精细失效。

**判据**
1. 新语义测试（值先量后写）：commit 后立刻查，必须反映新 HEAD；分页/重入不串味；
2. 新变异体 `epoch-bump-off`（关掉失效）必须被该测试杀掉 —— 沿用现有 catalog 纪律；
3. P0 基准台上 blame 类端点，第 2 次起 median 下降 ≥ 30ms；
4. 全套守卫不红。

**停机条件**：blame 在基准仓上本来 < 60ms → 缓存没有肉的证据，P3 降级为「只缓存 subject_of 这类零风险项」。

## P4 · 常驻 git 进程（`cat-file --batch`）

**性质**：这不是提速补丁，是**故障形态的更换**。因此：
- 先以显式开关提供（沿用 `aigit_perf.py` 已建立的「默认关、opt-in」模式，
  默认关闭的理由见 `aigit-E13-perf-layer.md` §4）；
- 稳定期后再谈默认翻转，**需用户明确授权**。

**范围**：文件读取 / diff / 冲突解决读 blob 的热路径；其余路径保持 `_run`。

**必须新增的判据（先于实现写好）**
1. **旧形态探针**：先在当前实现上录下「不存在 blob / 损坏 blob / 仓不存在」三类故障的
   错误归类签名（`code=` 与 HTTP 码）；
2. 新实现下三类签名**逐字一致**——否则不是提速，是改了对外契约；
3. 进程死亡/半截响应：`kill` 常驻进程后，下一请求必须自愈（重 spawn）且不返回半截数据；
4. 基准台上该路径延迟下降 ≥ 40ms（即至少省掉一次 spawn）。

**停机条件**：任何一条故障签名不一致 → 该路径回退 `_run`，只在 P2/P3 层面收工。

## 4. 风险登记

| 风险 | 触发点 | 缓解 |
|---|---|---|
| 旧报告数字腐坏（A5 的 206 结论过期就是实例） | 引用任何文档结论前 | 先读代码/先重测；P0 判据要求基线自查 |
| 基准台自身失真 | P0 | 校准段（裸 git 地板价 + 模型误差界）必须打印 PASS/FAIL |
| 缓存喂过期数据给守卫 | P3 | 红线：工作区状态永不缓存；`epoch-bump-off` 变异体钉住失效逻辑 |
| 常驻进程改变错误契约 | P4 | 故障签名先录后改；不一致即回退 |
| 性能改造动摇安全语义 | P2–P4 | 每阶段跑 28 变异体；新增守卫逻辑同步进 catalog |
| 默认开启未评审 | P4 | 沿用 opt-in + 稳定期 + 用户授权 |

## 5. 红线（不可谈判）

1. 不缓存工作区状态（status/dirty/diff）—— fail-closed 守卫的输入必须现算；
2. 不为提速跳过任何守卫（越界闸、add 作用域、确认协议、脏区拒绝）；
3. 不把 `--root` 指向真实仓做基准/探针；
4. 不改判据来「让数字变好」；判据变化必须写明原判据为何不成立；
5. 所有数字带命令与退出码；不可复现的数字不进本文档。
